# ТЗ: надёжность NetMeter macOS

Дата: 2026-11-16. Основание: аудит текущего кода и журналов приложения.

## 1. Цель и ограничения

Достоверные метрики, независимые сохраняемые настройки, диагностируемые ошибки,
предсказуемая работа после сна/смены сети, безопасная воспроизводимая сборка.
Рабочий каталог: текущий checkout. Ничего не публиковать, не отправлять в GitHub,
не создавать теги и не менять ключи подписи. Не включать/выключать автозапуск или
разрешения macOS пользователя при тестировании. Не останавливать посторонние приложения.
Существующая незакоммиченная доработка GPU core count и четыре перевода сохраняются.
Приложение остаётся Universal arm64/x86_64 с минимумом macOS 13.

Приоритет означает порядок реализации, а не разрешение пропустить следующие пункты.
Все пункты P0–P2 ниже входят в текущую работу. P3 — документированный будущий план.

## 2. Организация трёх агентов

1. **implementation** — владеет исходниками, ресурсами, сборкой, документацией;
   реализует требования последовательно P0 → P1 → P2 и исправляет замечания двух проверяющих.
2. **spec_control** — независимо проверяет соответствие каждому ID этого ТЗ;
   ведёт `docs/qa/SPEC_CHECKLIST.md`, отправляет исполнителю конкретные пропуски.
   Исходники не меняет. Не принимает наличие кода как доказательство работы.
3. **qa** — владеет новыми/дополненными файлами тестов и `docs/qa/TEST_REPORT.md`;
   воспроизводит ошибки, проверяет исправления и регрессии, сообщает обоим агентам.

Каждый агент сообщает двум другим и координатору о начале работы, существенной
находке, готовом этапе и блокере. Исполнитель сообщает точные файлы и команды,
после которых QA может тестировать. Не запускать одновременно две сборки в один
staging/module-cache. QA согласует тяжёлые сборки с исполнителем; артефакты тестов
размещаются в `.build/qa` или временном каталоге. При споре сверяться с ID требования.
Координатор принимает итог только после сверки отчётов контролёра и QA.

## 3. P0 — корректность показателей и сохранность настроек

### P0-NET-01. Настоящие 64-битные сетевые счётчики

- Заменить чтение 32-битных `if_data` на доступный macOS API с 64-битными RX/TX.
- Различать недоступные данные, нулевую скорость, смену интерфейса и сброс счётчика.
- Сброс одного направления не должен терять корректные данные другого.
- Использовать монотонное время. Первый замер и сброс дают новую базовую точку,
  а не ложный пик; недоступность не выдаётся за подтверждённый нулевой трафик.
- Сессионные и накопленные итоги учитывают только корректные положительные дельты.
- Тесты: переход через 2^32, большие значения 64 бит, reset RX/TX по отдельности,
  отсутствующий интерфейс, reconnect, нулевой/отрицательный интервал, большие паузы.
- На этом Mac выполнить короткое чтение с независимым системным источником;
  результат может отличаться из-за времени опроса, эти границы указать в отчёте.

### P0-SET-01. Независимость общих и индивидуальных настроек

- Выделить небольшое единое хранилище настроек с тестируемым isolated suite.
- Смена максимума шкалы не меняет сетку, подписи или уровень окон.
- Смена сетки меняет только сетку; смена подписей — только подписи.
- Общее действие «для всех» применяет только явно выбранное свойство ко всем
  графикам и согласованно сохраняет его. Индивидуальное действие меняет один график.
- Объяснить и зафиксировать в коде/документации приоритет global/per-graph.
- Миграция старых UserDefaults без потери пользовательских цветов, шрифтов,
  единиц, геометрии, видимости, склейки и итогов. Не переименовывать bundle ID.
- Проверить restart round-trip для global/per-graph комбинаций и отсутствие
  несвязанных изменений. Не использовать реальные настройки пользователя в тестах.

## 4. P1 — сбор метрик, диагностика, устойчивость

### P1-MET-01. Сбор вне главного потока

- Сериализованный сбор CPU/RAM/GPU/disk/network вне main; UI получает snapshot на main.
- Внешние процессы ifconfig/netstat имеют ограниченное время выполнения и корректное
  завершение. Не допускать параллельных зависших опросов и накопления задач.
- Частота около 1 секунды; открытое меню/системная панель не останавливает сбор.
- История учитывает реальный интервал/время: после сна не изображать паузу как
  непрерывный поток секундных измерений; сбрасывать baseline при необходимости.
- Скрытые графики не требуется постоянно перерисовывать; данные собирать соразмерно
  функционалу. Кэшировать дорогие неизменяемые значения/объекты разумным образом.

### P1-MET-02. Восстановление датчиков

- GPU и диск повторно обнаруживаются после временной ошибки/сна/смены устройств
  с ограниченной частотой; восстановление не требует рестарта приложения.
- Недоступные данные отображаются явно. Не угадывать количество ядер или скорость.
- При нескольких GPU явно описать, какая метрика показывается (текущий наиболее
  загруженный GPU допустим, если это понятно); число ядер относится к тому же устройству.
- Добавленный локально GPU core count сохранить; перевести новые строки на 4 языка.

### P1-LOG-01. Диагностика

- Добавить системное структурированное логирование: запуск/версия, смена сети,
  reset/недоступность/восстановление датчика, ошибка внешней команды, ошибки обновления,
  сохранения/миграции настроек. Не писать каждую скорость каждую секунду.
- У повторяющихся ошибок есть ограничение частоты. Не писать секреты, полные
  пользовательские пути, SSID/BSSID/MAC/IP без необходимости.
- Добавить «Экспорт диагностики»: версия/сборка/архитектура/macOS, доступность датчиков,
  обезличенные настройки и ограниченный журнал событий/ошибок. Пользователь выбирает
  место сохранения. Нет скрытой отправки или автоматического облачного экспорта.
- Ошибки Sparkle доступны диагностике; при неверной конфигурации причина видна.
- В тесте убедиться, что в экспорте нет ключей, токенов и лишних данных пользователя.

### P1-UPD-01. Sparkle и ссылки на архивы

- Обновить закреплённую Sparkle 2.9.2 до стабильной 2.10.1 (или более новой стабильной,
  если проверено по официальному релизу), с закреплением SHA-256 и проверкой подписи.
- Версия зависимости задаётся в одном месте, без рассинхронизации скриптов и README.
- Ссылки DMG внутри подписанной ленты привязаны к конкретному `vVERSION`, а не latest.
  Сам URL ленты latest может сохраниться для совместимости существующих установок.
- Сохранить SURequireSignedFeed и SUVerifyUpdateBeforeExtraction; не экспортировать
  приватный ключ. Отсутствие Keychain в тестовой среде явно отмечается, не обходится.
- Проверить feed/version/размер/подпись и отказ для подменённых feed/archive.
- Не менять текущую версию продукта и не публиковать релиз в рамках этого задания.

### P1-BLD-01. Чистая воспроизводимая сборка

- Новая сборка начинается с чистого bundle/staging, не подхватывает удалённые файлы.
- Копирование bundle корректно обрабатывает symlink/file/dir без записи через
  устаревшую ссылку в назначении; удаляет устаревшие компоненты в пределах назначения.
- Не удалять пользовательские настройки и текущую работающую .app во время сборки.
- Запретить пересекающиеся сборки в один staging либо дать изолированные каталоги.
- Проверить Universal, macOS minimum, Info.plist и `codesign --verify --deep --strict`.
- Новый CI для исходников: тесты и сборка на macOS без доступа к приватному ключу,
  с read-only permissions. Подготовить файлы локально, не активировать публикацию.

## 5. P2 — интерфейс, интеграция, документация

### P2-UI-01. Шрифты и подписи

- Заголовок сети остаётся в одну строку. Автоподгонка учитывает доступное место;
  выбранные крупные шрифты не обрезаются фиксированным прямоугольником по высоте.
- Аналогичные правила для ресурсов и per-core CPU, где применимы: нет наложения
  подписей на график или друг на друга. Учитывать маленькие окна и длинные локализации.
- При отключённой автоподгонке обеспечить достаточную геометрию/минимальные размеры
  либо явное доступное усечение с полной подсказкой; не молча прятать значения.
- Настройки/палитры отражают текущие выбранные цвета/шрифты после изменения через меню.
- Проверить все четыре языка и RTL, темную/светлую тему в доступных условиях.

### P2-SYS-01. Мониторинг системы и окна

- Не полагаться только на ровно пять радиокнопок и их порядок. Ограниченный поиск
  нужных элементов/идентификаторов, проверка кодов ошибок AX.
- При отсутствии разрешения или изменившемся UI открывать приложение и давать
  понятный результат/доступ к инструкции повторно, без постоянных модальных окон.
- Полностью недоступную/непроверенную GPU History не объявлять успешно открытой.
- Сохранить существующие отдельные меню графиков, движение групп и Option-detach.
- Проверить возврат CPU из всех ядер к стандартному размеру, сохранение окон и
  размещение в доступной области экрана после смены мониторов.

### P2-RAM-01. Память

- Исправить GB на GiB там, где деление на 1024^3.
- Добавить отображение фактического swap и доступного системного memory pressure
  (с явной недоступностью, если API/разрешение не позволяет). Не выводить pressure
  из одного лишь процента занятой памяти. Сохранить читаемость основного графика.
- Документировать формулу used memory и отличие от отдельных метрик Activity Monitor.

### P2-QA-01. Тесты и документация

- Сохранить существующие тесты; новые покрывают найденные дефекты и граничные условия,
  а не дублируют присваивания. Переводы без пропусков/пустых значений/разных placeholders.
- Интеграционные проверки настроек, сборки/подписи и диагностического экспорта.
- QA отчёт содержит: команды, результат, платформу, PASS/FAIL/BLOCKED и причину;
  static inspection не называется live E2E, unavailable hardware не называется tested.
- Обновить EN/RU README и docs/updates.md под фактическое поведение, включая GPU,
  новые ошибки/диагностику и ограничения ad-hoc. Удалить вводящие в заблуждение обещания.
- Контрольный список содержит каждый ID P0–P2 с доказательством и остаточным риском.

## 6. P3 — будущие задачи, сейчас не внедрять

- Статистика по дням/неделям/месяцам, экспорт истории и лимиты трафика с уведомлениями:
  сначала согласовать хранение, сроки, часовой пояс, параметры и запрос разрешений.
- Developer ID/notarization: нужны учётная запись и сертификат владельца; не создавать
  их, не запрашивать секреты и не отключать Gatekeeper в качестве обхода.
- Лицензия основного проекта: владелец выбирает условия; не назначать MIT автоматически.
- Проверка на физическом Intel Mac/других GPU и долгий замер утечек памяти:
  оформить матрицу необходимых проверок, честно указать доступность оборудования.

## 7. Приёмка

Готово, когда каждый P0–P2 реализован и проверен по доступным условиям, нет открытых
критичных/высоких замечаний, локальная сборка проходит проверки, оба независимых
агента согласовали отчёты. BLOCKED допускается только с конкретной внешней причиной
и явно выделяется в итоговом сообщении; не заменяется словом PASS.
Никаких git push, релизов, изменения автозапуска, разрешений или перезапуска текущего
экземпляра без отдельной необходимости и команды пользователя. Итог: рабочие локальные
изменения + два отчёта проверки + перечень того, что невозможно проверить здесь.

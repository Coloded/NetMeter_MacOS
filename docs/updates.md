# Обновления «Трафик»

В приложение встроен Sparkle **2.9.2**. Его официальный архив загружается из
`sparkle-project/Sparkle`, проверяется по закреплённому SHA-256 и включается в `.app`.
Исходная конфигурация находится в `updates/config.json`, шаблон Info.plist — в `Resources/Info.plist`.

Пока `repository` пустой, Sparkle не запускает проверку и ничего не скачивает.
В меню строки macOS есть «Проверить обновления…» и «О программе…».
Во вкладке настроек «Обновления» есть ручная и ежедневная автоматическая проверка.
Установка предложенного обновления требует действия пользователя.

## Подключение репозитория

После получения адреса репозитория:

```bash
python3 scripts/update_config.py --repository OWNER/REPO
bash build.sh
```

Адрес ленты будет сформирован автоматически:
`https://github.com/OWNER/REPO/releases/latest/download/appcast.xml`.
Публичный ключ и адрес ленты встраиваются в приложение при сборке.
Первую сборку с адресом репозитория нужно установить вручную; сборка без адреса
не сможет самостоятельно найти первый выпуск.

## Ключ подписи

У этого приложения свой ключ: аккаунт Keychain `local.traffic.meter.sparkle`.
Приватный ключ остаётся в macOS Keychain. В проект записывается только публичная часть.
Для первоначальной подготовки на машине выпуска:

```bash
bash scripts/setup_sparkle.sh
python3 scripts/setup_update_key.py
```

Если публичный ключ проекта отличается от ключа в Keychain, скрипты отказываются
его заменять или подписывать выпуск. Потеря ключа мешает дальнейшим обновлениям;
сохраните доступ к Keychain машины выпуска.

## Новый выпуск

Версия и номер сборки задаются в `updates/config.json`. Номер сборки должен
увеличиваться при каждом выпуске: именно его сравнивает Sparkle.

```bash
python3 scripts/update_config.py --version 1.0.1 --build 2
# Обновить updates/release-notes.md
python3 scripts/prepare_update.py
```

Скрипт собирает одно приложение, из него создаёт `NetMeter-stable.dmg`,
проверяет DMG, генерирует подписанную `appcast.xml` и проверяет обе EdDSA-подписи,
адрес архива, размер, версию и номер сборки. Описание изменений включается в ленту.
Выпуск сохраняется в `dist/release-vVERSION-buildBUILD/`.
Повторная подготовка в существующий каталог запрещена, чтобы случайно не заменить выпуск.

В соответствующий **GitHub Release** нужно загрузить из этого каталога:

- `NetMeter-stable.dmg`;
- `appcast.xml`;
- `SHA256SUMS.txt` — дополнительная проверка файлов.

Этот выпуск должен стать `latest`. Приложение не использует GitHub API для поиска
DMG: оно читает appcast и передаёт скачивание, проверку, установку и перезапуск Sparkle.
Скрипты ничего не публикуют в GitHub автоматически. Приватный ключ для CI не требуется.
Готовые файлы после подписи изменять нельзя; ленту и DMG следует публиковать вместе.

## Проверки

```bash
bash build.sh --probe
python3 Tests/test_updates.py
python3 Tests/test_updates.py --dmg
python3 scripts/verify_update.py dist/release-v1.0.1-build2
```

Тест подписей создаёт локальный тестовый ZIP (с `--dmg` — DMG) с адресом `example.invalid`,
проверяет его и затем убеждается, что изменение ленты или байтов архива отвергается.
Он не обращается к тестовому адресу, не меняет настройки реального репозитория
и не устанавливает тестовую версию приложения.

Обязательная проверка подписанной ленты (`SURequireSignedFeed`) и проверка архива
до распаковки (`SUVerifyUpdateBeforeExtraction`) включены в каждой сборке.
Universal-сборка (Apple Silicon и Intel) рассчитана на macOS 13 и новее. Сейчас приложение подписывается
локальной ad-hoc подписью; Developer ID и notarization требуют отдельной настройки
учётной записи Apple Developer.

Документация: https://sparkle-project.org/documentation/
